EXPOSURE / EVALUATION MEANING
Transaction size
CLI --useful-bytes=472. Canonical encoded request = useful +
60 bytes (532 at default).
CLI --useful-bytes=128. Native signed BCS size is measured;
accepted 128-byte payload produced 409-byte transactions.
Match useful bytes; also record actual
serialized sizes. Equal useful size does not
mean equal wire size.
Input rate / horizon
CLI --rate=1000 total tx/s; warmup 10 s, measure 30 s, drain 30
s. Independent open-loop ingress.
CLI --interval-us=1000; --counts=16/origin. Four origins imply
nominal 4000 tx/s, but only 64 finite requests.
Raptr runner is finite conformance, not a
sustained-load adapter yet. Preserve
rejection and unfinished counts.
Batch tx count
CLI --max-batch-transactions=128; also constrained by encoded
byte capacity.
JSON quorum_store.sender_max_batch_txns=500;
sender_max_total_txns=500; sender_max_num_batches=1 per pool
pull.
Count limits are available. Batch cutting
remains core policy; settings alone do not
match batch fill.
Batch byte cap
FIXED MAX_BATCH_PAYLOAD=256 KiB. Count <=
floor((262144 - 8)/(useful + 60)).
JSON sender_max_batch_bytes=1,048,416 is not enforced by the
native splitter. Total pool-pull bytes=4,194,144 is enforced.
Pre-cloud gap: expose an enforced Delugi
byte cap; review native Raptr byte-splitting
behavior before sweeping it.
Batch cadence
CLI --batch-ms=10 (1..1000 ms). Flush on capacity or elapsed
cadence.
JSON QS poll=150 ms; min nonempty=80 ms; max=300 ms; native
dynamic backpressure also applies.
Different native batching policies. Record
effective cut times and fill, not just a common
label.
Proposal bytes / tx
Resource profile: 1 MiB or 32 MiB ordering wire budget.
Value+witness allowance reserves mandatory HISTORY3
overhead.
JSON consensus.max_sending_block_txns=50,000;
max_sending_block_bytes=30 MiB; inline=100 tx / 200 KiB.
Separate proposal budget from transport
frame limit. Raptr message limit is separately
1 MiB by default.
Max payload batches
No independent max_payloads switch. A frontier checkpoint can
cover many batches; MMR chunk capacity is not a batch-count
cap.
JSON max_batches_per_pull=200; current native > checks can
select 201. Native subblock count is fixed at 8.
Use explicit names: batch bytes, tx per batch,
batches per proposal, proposal bytes, frame
bytes.
Protocol bound Δ
CLI --bound-ms=250 default; acceptance used 100. PROG
pacing defaults to Δ; native 7Δ / 3Δ catch-up rules remain.
JSON delta_ms; accepted runner fixes 100. Leader 4Δ; partial-QC
wait 0.1Δ; fetch 2Δ; sync 15Δ; status 10Δ.
Δ is protocol configuration. It is not added
network delay, nor a latency scoring deadline.
Network delay δ
External calibrated shaper. macOS helper 1..100 ms; Linux
ingress netem delay 0..1000 ms and loss 0..100%.
No node delay knob. Current runner records 0 ms added delay;
future deployment can reuse the external shaper.
Keep δ, Δ, batching and application hold
distinct. Current helper schema has no
bandwidth/jitter knobs.
