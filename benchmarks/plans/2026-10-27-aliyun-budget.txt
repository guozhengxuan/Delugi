Delugi: compact Aliyun evaluation budget and load-point audit
27 October 2026 (Asia/Taipei), revised after the author's scope correction

Decision
--------
One 60-second run per configuration. Six coarse load points per curve, with at
most two supplemental points or selective reruns. Exactly 10 and 50 replicas.
The user ceiling is the available Aliyun cash balance at the read-only snapshot
plus CNY 2,000. The additional allowance is not a completed top-up transaction.
The balance and resolved ceiling are retained only in the ignored private file:
  results/local/aliyun-budget-20261027/account-balance.json

Estimate CNY 516–921 for the compact campaign, including build time, bounded
collection, optional points and 25% contingency. Allocate CNY 1,000 within the
user ceiling. The previous 1,554-trial, CNY-20,000 regional / CNY-35,000 combined
study is superseded; its historical calculation remains at commit 9a91b1e.
There is no requirement to spend the remaining allowance.

The six implementations remain Delugi, integrated Raptr, Opt-Mempool-Simple-IT,
Opt-Dispersed-Simple-IT, original Autobahn and Mysticeti-C. Implementation,
conformance, evidence and 50-replica quorum gates still apply. No cloud resources
were created by this revision. The budget JSON is a planning model, not a run
configuration accepted by the current deployment CLI.

Input-load controls: paper and source findings
----------------------------------------------
Raptr's experiment description uses open-loop clients, each connected to one
replica. It varies client threads/request cadence to reach the target TPS;
its example of one request per millisecond yields 1,000 tx/s per such client.
Keep the offered load independent of consensus completion. The paper ran each
experiment for five minutes; this campaign follows the author's new 60-second
instruction instead of copying that duration.

Simple-IT's paper increases generated transaction load until throughput stops
rising and latency increases. It uses 60-second n=10 and 120-second n=50 runs.
For dispersed variants, the leader generates transactions when proposing.
The requested campaign will use 60 seconds for both committee sizes.

The inspected author mempool pin, 164c139d375bb958b41f59b6e6ca5e06ac2f2fe9:
* benchmark/benchmark/remote.py:378–396 divides configured rate among worker
  groups for the external-client path; with multiple workers its allocation
  needs checking rather than assuming the configured total is the actual sum.
* node/src/benchmark_client.rs:86–102 sends floor(rate/20) transactions every
  50 ms. Integer rounding and client backpressure affect the achieved offer rate.
* remote.py:522–529 skips external clients when consensus_only=true; its loop
  at 735–736 iterates burst settings while taking only rate[0].
* primary/src/proposer.rs:83–103 constructs header_size/tx_size anonymous
  transactions directly. Thus changing a rate field alone does not establish
  independent transaction arrival in this artifact.
The inspected dispersed proposer similarly generates payload at proposal time
in consensus_only mode. Qualify the chosen failure-capable revisions separately.

For the common end-to-end series, use one global honest offered-rate parameter R,
split across active honest origins with deterministic fractional scheduling.
Record both requested and actual rates, admission, completion and unfinished
work. Preserve native batching/proposal rules; use identifiable independent
arrivals in adapters. An author-style proposal-generated consensus-only run
must be labeled separately, since it omits pre-proposal waiting. The inherited
Simple-IT benchmark defaults are source evidence, not proof that its artifact
is ready for matched end-to-end measurements.

Compact configuration and scope
-------------------------------
Main profile: Singapore, ecs.g9i.xlarge, one validator per host, 200 GiB ESSD,
512 useful bytes/transaction, 100 Mbps aggregate private protocol egress,
added one-way delta=10 ms and Delta=100 ms with native timer relationships.
Freeze one supported batching/proposal configuration per implementation.

Initial TOTAL honest offered rates per committee:
  [1,000, 4,000, 8,000, 16,000, 32,000, 64,000] tx/s
Use the same initial rates across implementations; do not multiply R by n.
If saturation lies outside this grid, use a coarse extension from the shared
allowance. Retain overload/failure results and stop pathological resource growth.
No fine-grained binary search or blanket three repetitions. If repeated runs
are needed, consume the same supplemental allowance rather than adding a second
matrix. A single run does not provide between-run error bars.

Main run: ready/connect first, then offer and measure for 60 seconds; no extra
offered-load warmup. Drain for at most 15 seconds without creating more input.
Preserve unfinished work when the drain expires. Publication, preparation,
evidence export and cleanup are separate billed operations, not extra load time.

The two fault cases are one recoverable missing-data impairment and one native
silent-leader opportunity, each at one common offered rate below the observed
healthy frontiers. For Delugi retain the silent leader plus three honest anchors.
Use a qualified comparable impairment; document protocol-specific block/payload
semantics. Select a finite fault interval early enough to observe recovery in
60 seconds. Cases without a valid native actor remain unqualified.

Reuse healthy and fault traces for latency decomposition, traffic and resource
figures. Extra payload sizes, CPU/bandwidth/timing sweeps, Byzantine variants,
scheduling ablations and WAN campaigns are outside this compact paid scope.
Keep required protocol and observer conformance checks local before deployment.

Cost calculation
----------------
Live read-only DescribePrice quotes at 2026-10-27 09:27:34 UTC:
  Singapore validator + 200 GiB + 5 Mbps public: CNY 2.0833/host-hour
  Ten validators: CNY 20.833/hour; fifty: CNY 104.165/hour
  Build host g9i.2xlarge + 200 GiB + 5 Mbps: CNY 3.5197/hour
The disk and fixed public management bandwidth are included once. Benchmark
traffic stays on private VPC links; 100 Mbps is the protocol shaper, not a
100 Mbps purchased Internet connection. No WAN traffic or paid network services
are included. Quote receipts/hashes are retained in the companion JSON.

A one-minute healthy sweep alone costs about CNY 75 in active validator time.
The full operational estimate also includes the remaining tests and these costs:

Use one reused fleet across protocols and release excess hosts between sizes.
Each fleet lease lasts at most three hours, with up to 30 minutes of setup and
cleanup and 2.5 hours of trial slots. The conservative case needs two sessions
for each formal size; the fast case needs one. Build before fleet allocation.
The build allowance covers up to 24 billed host-hours across finite sessions;
use retained compatible artifacts when possible, and remove disposable targets.

Conservative collection allows up to 0.08 GiB compressed evidence per host per
trial: about 137 seconds at 5 Mbps, plus a short drain and reset in the remaining
slot allowance. The fast case needs smaller archives or a faster qualified
collection path. Measure actual archive sizes and collector throughput during
qualification; do not discard required evidence to force the estimate to fit.
Reprice or reduce optional work if observed time exceeds the slot allowance.

For each row: trials x replicas x billed_slot_minutes / 60 x hourly_price.
Then add lease setup and build hours, and 25% reserve. The maximum 24 optional
runs and contingency are included, not costs to add again afterward.

Budget enforcement and remaining implementation work
----------------------------------------------------
The initial working allocation is CNY 1,000; the aggregate user ceiling remains
snapshot cash balance plus CNY 2,000. Carry spending between leases in one ledger.
Refresh prices and available funds before starting leases. Reserve export and
cleanup before scheduling another trial, and release resources on gate failure.
The earlier CNY-50 pilot is complete and is not a new allocation.

Keep the existing CNY-500 per-lease guard: fifty hosts for three hours cost
CNY 312.50 before margin, or CNY 390.62 with 25% reserve. Extend the reviewed
31-host capability to exactly fifty and support the build profile; do not simply
disable guards. The current runner/adapters still need the sustained ingress,
common evidence, Simple-IT authentication/output, and general-membership work
already listed in IMPLEMENTATION_PLAN.md. These prices do not establish readiness.
