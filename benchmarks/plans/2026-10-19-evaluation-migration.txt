Measurement contract
1. Useful-output performance: sustainable unique honest application goodput versus admission-to-origin-local payload-verified contiguous output latency. Origins are preassigned correct ingress replicas with balanced cohorts. Use one monotonic clock. Record intended submission, actual ingress/admission, batching, output, rejects and backpressure. Report scheduled submission-to-output as well. p50/p95/p99 must retain unfinished cohorts; undefined/above-deadline quantiles remain visible. Stable capacity requires stable backlog and repeated multi-minute trials.
2. Robust completion: all-correct cohort completion, worst honest-origin completion by fixed deadlines, oldest outstanding request and backlog recovery. Remote completion notifications measured on the origin clock are observed completion including return delay. Exact remote event timing requires calibrated clocks. Compare output prefixes within each protocol execution; different protocols may choose different valid orders.
3. Resource cost: total committee and hottest-replica outbound bytes, split payload, evidence/control, repair and transport overhead; signing/verifying/proof CPU and retained memory. Count each network transmission once, not both send and receive. Separate ordinary protocol signatures from transport authentication.
Keep exact distinct emitted batch payload M_out separate from U_out, unique useful honest application bytes. Deduplicate the useful-goodput counter by authenticated request identity; preserve the protocol's actual output semantics. Report both denominators where faulty duplicate content can diverge. Do not sum replicated outputs. Declare the output replica/prefix and interval used. Charge all opportunities, including failed, empty, repeated-prefix work, delayed sends, optional source distribution, repairs, setup and carried-in evidence. Zero-output intervals retain total costs and an undefined ratio.
Input preparation, complete-proposal broadcast-to-direct-commit, descriptor delivery and payload materialization are diagnostic stages. They do not replace useful output.

Three main experiment families
A. Healthy useful-output and resource frontier. Load from sparse to saturation; tune native batching and certified-unit size under the same tail-latency target; include small and larger committees. Expose Delugi-unfavorable sparse progress, proof CPU, cubic metadata and large competitor certified units. Compare at identical offered workload; report each system's sustainable frontier. Initial diagnostic n=4, then validated n=7 and n=31. Current code does not yet support the latter.
B. Correct-leader responsiveness and payload disruption. At a common offered load below the smallest healthy capacity, hold actual δ and resources fixed while varying configured Δ. Include clean operation, a nonleader withholding/selectively publishing payloads, and transient loss. Keep TCP packet loss distinct from application-message omission, and data-only impairment distinct from all traffic. Preserve native validation, recovery, leader selection and reputation; do not force an unavailable reference through validation or delete honest custody to manufacture an attack. Use a fixed set of at most f faulty identities. Add a secondary matched-utilization comparison. Reverse the δ/Δ sweep at selected points. Record valid empty inputs despite pending honest data, constructor source/proof readiness, fresh useful output, repairs and ordering latency separately. Use witnessed actual delay so queueing is not mislabeled as a timeout effect.
C. Faulty-leader continuity and recovery. Begin with one silent leader followed by honest leaders, then fault bursts within the fixed f-node fault budget, selective publication, and sustained versus withdrawn attacks. Three subsequent honest Delugi anchors are a diagnostic; retain each counterpart's native schedule. Follow every honest-origin cohort through the declared drain/deadline; measure proposal fate and transaction replay separately, output gaps, worst-origin completion and backlog recovery. Include an unfavorable case in which descriptors commit but payload recovery blocks contiguous output.

Required ablation
Immediate versus paced originating PROG crossed with bundling off/on, all using the same bounded pipelined transport, queues, authentication and validation. Bundling has no fill timer. Pacing tests establish behavior; theorem coverage needs its own argument. Historical-source reuse remains disabled in reference results; expanded historical evidence is optional work with its own cost ledger.

First implementation increment
Provenance selection plus four-process independent-arrival and exact-materialization cohort accounting. Start with Delugi healthy and finite-disruption runs; normalize the existing Mysticeti adapter in parallel for the first matched pilot. Use common useful application bytes, explicit scheduling mode, complete deadline/drain results and reconciled resource counters. Accept an incomplete cohort and a zero-output case as accounted outcomes, not invalid experiments. Larger committees, fragmentation and new protocol implementations do not block this increment.

Decision rules
- More commits without more useful output is not a useful-throughput improvement.
- Every protocol may tune certified units under the same latency requirement. If grouping erases a cost advantage, report that operating region directly.
- Stable capacity requires non-growing queues; completed-only latency cannot hide backlog.
- Descriptor speed must be followed through materialization and honest-origin completion.
- Separate direct-commit responsiveness under stated input/alignment conditions from recovery and end-to-end output. Do not transfer the paper theorem to the paced implementation based on tests.
- Separate native implementation results from claims about isolated protocol effects when storage or transport services differ.
- Finite deadline misses establish observed completion failures; they do not prove permanent censorship.
