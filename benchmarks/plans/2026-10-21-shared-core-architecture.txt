Approved direction

Refactor the current Delugi repository into a Rust workspace with one shared
runtime and selectable protocol cores. Raptr is the first counterpart. Preserve
the pinned native author artifacts as reference implementations and external
validity checks. Keep all protocol-dependent behavior inside core/<protocol>,
including dissemination and recovery policy, not just voting and commit rules.
Use Sonnino's modular family as an architectural reference, not as a wholesale
replacement or an assumption that all historical branches share infrastructure.

Existing baseline checkout and evidence paths remain intact during migration.
No Shoal port is a prerequisite. Further counterparts follow the first accepted

Shared mechanism versus core policy

Shared mempool owns admission and byte construction, not a universal availability
certificate. A core requests batch cuts and decides what is disseminated, when
it is considered available, which peers store it, and whether it may be proposed.
Raptr's Quorum Store rules, Mysticeti's uncertified causal data, Autobahn's lanes,
and Delugi's observations/witnesses remain different implementations in core.

Shared network accepts bounded opaque bytes with protocol/version/run/domain and
channel identity in its service context. These are initially out-of-band adapter
metadata; mechanical extraction must not add fields to existing wire bytes or
replace existing authenticated namespaces. A new common wire profile is a
separate reviewed change. It owns connection reuse and fair queue service. A queued send,
successful socket write and acknowledged receipt are distinct events; none is
an availability certificate. No frame-by-frame application ACK gate. Reliability,
replay, cancellation and control/data queue profiles are declared and identical
for a matched trial; protocol retransmission policy remains in its core.

Shared crypto supplies implementations, not one imposed proof format. Preserve
each algorithm's ordinary signatures, aggregation, threshold assumptions, signer
sets and verification rules. Core owns what is signed and certificate validity;
the provider owns cryptographic execution and accounting. A changed proof scheme
is a separately named variant, never an undocumented normalization.

Shared store distinguishes accepted, visible, written and durable operations.
Visible means a declared process-local read sees the value; it does not imply a
write reached the OS. Written means the selected backend completed its specified
write operation, potentially only to an OS buffer; no fsync is implied. Durable
requires the manifest's declared synchronization and persistence fault model.
Unsupported durability requests fail explicitly, never downgrade silently.
Core decides persist-before-vote/custody, retention, garbage collection and
recovery rules. Common backend/settings must be stated. No storage operation
may implicitly authorize a vote. In-memory or no-crash profiles cannot support
durability/restart claims, and replacing native durability needs explicit scope.

Core determines canonical committed descriptors and within-descriptor order.
Shared output waits for the required locally verified payloads and publishes a
contiguous prefix. It must not sort across protocol decisions, drop an unavailable
head, or deduplicate distinct fork batches on application identity. Exact batch
deduplication is protocol-owned; unique useful-request counting is evaluation
logic. Raw duplicate/unknown occurrences remain evidence.

Minimal integration interface

Node selects a core factory once, for example --protocol delugi|raptr. Shared
services must not import protocol crates or branch on protocol names. Protocol
message types/codecs, settings and semantic fault opportunities are registered
by each core. Opaque bytes do not justify unbounded decoding or allocations.

Ditto MAIN provides a concrete same-binary precedent: its node selects two-chain
HotStuff, Ditto/AsyncHotStuff or TwoChainVABA while starting the same shared
services. Its separate historical3-chain branch also changes infrastructure;
branch comparisons are not evidence of shared-service equivalence. Pinned source
references and an actual blob comparison are in the HotStuff/Ditto audit below.

Inputs include admitted work/batch results, authenticated peer envelopes,
scheduled timer firings, local storage/crypto/fetch results, and resource pressure.
Outputs include send/fetch/persist/verify requests, timer operations, custody
release, committed output descriptors and diagnostic events. Each asynchronous
request has an operation ID; completion, failure and cancellation are explicit.
Effects that require a preceding durable or verification result wait for that
specific completion. Do not assume a returned list of effects completes in order.

Local state owners process their own events serially; network, storage, crypto,
dissemination and payload fetches may run concurrently under a common aggregate
resource budget. Do not put every protocol and worker behind one serialized
global event loop. Record event order, monotonic time, timer generation and random
choices for replay. Core defines timer policy/multipliers; runtime executes it.

Preserve existing actor entry points through adapters: Delugi Replica, Raptr
Protocol::run_ctx/Context and Mysticeti CoreThread. The logical event/effect
contract does not require rewriting every state machine into a new framework.
For Raptr, preserve handler-plus-condition-fixed-point atomicity, native BCS/BLS
types, and real QS policy initially. Minimal Aptos compatibility dependencies may
remain until equivalence tests justify extraction. The sim-types backend is not
a faithful shortcut. Native-only service calls in an intermediate facade must
be disclosed; that intermediate stage cannot claim a fully shared runtime.

Backpressure is explicit at every queue. Enqueue failure never silently drops a
required effect or rewrites application admission. Common priority policies must
not depend on whether a core calls a message VOTE, CER or a DAG block. Stage clocks
and message categories expose queueing and service costs without choosing safety
or liveness behavior.

semantic change additionally requires the author's decision.

Conformance and evaluation labels

The precise label is shared-runtime, native-policy protocol ports.
Shared-runtime measurements compare protocol implementations under controlled
common services. Pinned native measurements retain each author artifact's stack;
they provide fidelity and external-validity evidence, not interchangeable rows.
Do not merge their rankings or label a port an unchanged native artifact.
Record the common service hashes, selected provider/profile and complete per-core
call paths. Equal settings mean equal mechanisms and resource limits; protocol
policy may request different work and must pay its measured cost. A core that
bypasses shared network/storage/crypto machinery does not pass this label's gate.
Require a capability/call-path manifest and runtime service-operation/resource
counters reconciled against actual sockets, storage operations and crypto workers.
Undisclosed native service calls fail the shared-runtime label; source hashes and
configuration equality alone do not demonstrate routing through common services.

Within a protocol, replay equivalent semantic schedules and compare validated
inputs, decisions, committed sets/prefix refinements, repair obligations and
eventual output. Compare partial orders where concurrency is unconstrained.
Do not demand identical schedules or transaction order across different protocols.
Retain source mappings, cryptographic vectors, reference traces and adversarial
tests; conformance tests support an implementation claim, not a new proof.

Primary latency remains independent application admission to preassigned correct
origin-local verified contiguous output on one monotonic clock. Preserve scheduled
arrivals, rejection, backlog and unfinished cohorts. Report deadline and all-correct
completion, worst honest origin, goodput/tail frontier and absolute resource costs.
Keep distinct exact-batch payload M_out separate from unique useful honest U_out.
Charge crypto, storage, metadata, payload, recovery, transport and failed/empty work.
Do not subtract unsynchronized remote clocks. Keep actual delta independent of
operative Delta and batching; retain each timer mapping rather than equal labels.
