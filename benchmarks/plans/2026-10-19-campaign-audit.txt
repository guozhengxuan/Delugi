Remote runtime prerequisite (clarified during review, not an open blocker)
Formal resource proof includes an explicit swap policy. New inventories request
zero swap; dedicated hosts observe configured swap before/after execution, while
delegated cgroups enforce memory.swap.max. Legacy evidence without this binding
remains a diagnostic and is not promoted to verified formal resources. Current
resource contracts use schema2 with shared structural verification at both campaign
acceptance and frontier replay; a historical hash-valid success label does not
substitute for missing swap or per-host budget proof. Native
publication recipes must also match the fixed commands and every binary's actual
build sidecar; immutable publication metadata alone is insufficient.

Native placement explicitly requires a preinstalled selected Python >=3.10 executable and verifies version/realpath/hash. Inventory conversion preserves this selection; upload, bootstrap, RPC, supervisors and collectors use the declared executable. Delugi's remote worker, netem helper and preparation bootstrap remain Python3.8-compatible, using the declared interpreter when present and python3 otherwise. Ubuntu20.04 native runs must select a separately installed supported interpreter; Ubuntu22.04's Python3.10 is another supported prerequisite. Artifact publication does not install a newer interpreter. Preparation, placement, campaign and cleanup paths have local mocked/subprocess acceptance only; privileged Linux shaping and live cloud deployment remain outside the user's current scope.
