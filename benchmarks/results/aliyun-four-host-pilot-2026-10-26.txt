Delugi / Raptr: first four-host Aliyun pilot
26 October 2026
==========================================

Result
------
All 12 distributed functional trials passed. Both integrated protocols ran from
the same source-bound Linux release on four independent Singapore ECS instances.
Every trial collected all four hosts and confirmed cleanup of its owned process
groups. This completes the initial Linux artifact and four-host deployment gate.

Protocol  Case                         Repetitions  Useful transactions
Delugi    healthy through round 4       3/3 passed   32 at every correct replica
Delugi    silent first leader          3/3 passed   24 at every correct replica
Raptr     healthy through round 4       3/3 passed   64 complete at all 4 replicas
Raptr     silent first leader          3/3 passed   48 complete at all 3 correct replicas

Both silent cases require the three subsequent honest anchors. Delugi's silent
leader is replica 0; Raptr's native schedule makes replica 1 the first leader.
Delugi checks exact once-only transaction/batch output, state agreement, round
classifications, direct commitments, HISTORY3 and all-current composition.
Raptr checks authenticated finite inputs and native payloads, canonical output
prefixes, cohort completion at every correct replica and executor shutdown.
Its native verifier authenticates the observer archive and payload/order; the
export does not contain raw native QC bytes and makes no offline QC-verification
claim. Per-trial results and evidence hashes are in the adjacent JSON receipt.

Environment and measurement scope
---------------------------------
Four ecs.g9i.xlarge hosts, each 4 vCPU / 16 GiB provider RAM, 200 GiB ESSD system disk,
Ubuntu 24.04.5, Intel Xeon 6982P-C, swap 0. All four exposed 16335233024 usable RAM
bytes. Protocol traffic used private VPC addresses; public administration used
fixed 5 Mbps egress. All 12 directed private TCP connectivity probes passed.

Configured Delta was 100 ms and injected delta was 0. No 10 ms shaping or one-way
delay claim is made. Native protocol timer multipliers remained unchanged.
Storage was shared-rocksdb-written-v1: WAL enabled, synchronous fsync disabled.
Transactions contained 128 useful payload bytes.

Delugi preloaded two transactions per correct origin for each of four payload
heights before starting ordering. Its fixture reports no transaction latency.
Raptr offered 16 finite requests per correct origin at 1 ms cadence, with 100 ms
start delay, 5 s measurement and 5 s drain. Its per-trial latency is origin-local
CLOCK_MONOTONIC admission to the first actual application append. Completion at
every correct replica is checked as membership, without subtracting host clocks.

These finite workload shapes differ; comparison_eligible=false. Throughput and
latency rankings are not inferred. The JSON retains diagnostic traffic and
Raptr latency values. Delugi traffic drains completely; Raptr counters freeze
before shutdown and include its continuing idle consensus. Neither counts
IP/link headers or kernel TCP retransmissions.

All 19 native Linux tests passed, and each host verified the publication,
compiled-source receipt, architecture and library availability. Focused Python
checks passed: 14 provider, 87 build-job, 118 disk/resource, 3 Linux disk-sampler,
and 20 pilot/controller checks. These suites overlap and are not summed.

The live pilot exposed three engineering issues. A single-job RocksDB build
exceeded its 1800 second guard; cloud builds now use two jobs. A later build hit
a disk-sampling race when compiler temporary files disappeared; the sampler
now counts allocated blocks without following links, tolerates only vanished
entries and still rejects real I/O errors. Finally, short-lived SSH control
connections reset before authentication during the first Delugi trial. That
trial remains rejected, with recovered logs and confirmed process cleanup.
The controller now reuses campaign-owned pinned SSH sessions and closes them
afterward. The following full 12-trial campaign passed. These changes affect
build/controller tooling; consensus code and dependency versions were unchanged.
