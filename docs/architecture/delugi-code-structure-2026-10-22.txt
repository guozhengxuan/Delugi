1. The implemented boundary

node/src/shared_main.rs registers DelugiFactory and RaptrFactory. The retained
common artifact filename is raptr-shared-node; --protocol selects the core and
omission defaults to Delugi. The root lightweight delugi-node/delugi-replica
build remains Delugi-only. The common assembly manifest is core/raptr/node.

core-api contains a lifecycle facade, storage capability/completion types and
OperationId. It does not implement a universal consensus, availability,
transaction or output-sink interface. OperationId is declared but currently
unused by the runtime. The common factory reads opaque per-core JSON bytes:

  trait ProtocolFactory {
    fn name(&self) -> &'static str;
    fn run(&self, configuration: &[u8], id: u32) -> Result<(), String>;
    fn generate_keys(&self, directory: &Path, nodes: usize)
        -> Result<String, String>;
    fn verify_archive(&self, configuration: &[u8], path: &Path)
        -> Result<String, String>;
    fn verify_ledger(&self, configuration: &[u8], path: &Path)
        -> Result<String, String>;
  }

Source: core-api/src/lib.rs:44; node/src/lib.rs:6; node/src/shared_main.rs:4.

The cores reuse shared/network, shared/mempool and shared/output mechanisms.
shared/network-async is Raptr's async facade over the shared TCP implementation.
shared/crypto and shared/crypto-aptos retain protocol-specific cryptography.
Storage uses shared/store and shared/store-rocksdb. Scheduling still differs:
Delugi has a synchronous actor/control/timer loop; Raptr uses Tokio actors,
shared-runtime-async task ownership and native-compatible timers. Shared service
reuse is not a claim of equal executor topology or CPU/memory budgets.

2. Delugi consensus and composition interfaces

replica::Replica::try_new receives a callback:
  q: impl Fn(u64, &[u8], &[u8]) -> bool + Send + Sync + 'static
It is bound to AvailabilityConfig::q(round, value, witness) by composed::Node.
Inputs is BTreeMap<u64, (Vec<u8>, Vec<u8>)>, an immutable round-to-(x,pi) map.

  start(&mut self, now: u64) -> Result<Vec<replica::Effect>, String>
  receive(&mut self, now: u64, message: wire::Message)
      -> Result<Vec<replica::Effect>, String>
  tick(&mut self, now: u64) -> Result<Vec<replica::Effect>, String>
  supply_input(&mut self, now: u64, round: u64,
               value: Vec<u8>, witness: Vec<u8>)
      -> Result<Vec<replica::Effect>, String>

  replica::Effect = Send {to, message} | Wake {at}
      | DirectCommit {round, digest} | Deliver(Delivery)
      | Notice {kind, round}
  Delivery = {round: u64, digest: Digest, value: Vec<u8>}

Source: core/delugi/src/replica.rs:735,748,2177,2384-2430;
        core/delugi/src/scanner.rs:21.

process::Runtime drives composed::Node. Its public start/tick, produce(payload),
receive(from, Message), receive_ordering(wire::Message) entries produce composed
effects. REPORT/OBS construction supplies (x,pi) to Replica. Returned ordering
effects pass through Node::accept_ordering, which enqueues delivered descriptors
and attempts materialization, before Runtime::effects dispatches outgoing bytes,
timer wakes and diagnostics. Runtime does not implement scanner resolution.

Incoming DATA is authenticated by BatchStore::accept_requested_data or
accept_requested_part during Node::receive; retry then materializes held verified
records. A missing exact suffix emits FETCH and blocks the ordered FIFO head.
Exact batch identity is (producer,height,unsigned-header digest). Application
transaction-ID deduplication is separate from protocol exact-batch deduplication.

Source: core/delugi/src/composed.rs:144,210,242,385,419-441,491,532-671;
        core/delugi/src/process.rs:959,1983.

DirectCommit, ordered descriptor delivery and verified application output are
three different observation points. Neither missing application payload nor
application output completion becomes a prerequisite for the consensus vote.

3. Raptr consensus and dissemination interfaces

native/src/framework/mod.rs:36 defines the native Protocol trait. It has
associated Message and TimerEvent types and async handlers for startup, peer
messages, module events, timers and conditions. run_ctx retains native state
ownership across handler and condition evaluation.

Context (native/src/framework/context.rs:19) supplies node_id, n_nodes, sender,
send/unicast/multicast, module notify, set_timer, next_event and halt state.
The native raptr::dissemination::DisseminationLayer trait has:

  prepare_block(round, exclude: HashSet<BatchInfo>,
                exclude_authors: Option<BitVec>) -> Future<Payload>
  available_prefix(&Payload, cached: Prefix) -> Future<(Prefix, BitVec)>
  check_payload(&Payload) -> Result<(), BitVec>
  notify_commit_identified(Vec<CommittedPayload>, timestamp, voters)
      -> Future<()>

CommittedPayload binds block_digest, payload and include_proofs. The trait also
retains notify_commit and set_first_committed_block_timestamp. The figure shows
the interfaces relevant to the active common-node adapter.

Source: core/raptr/native/src/raptr/dissemination/mod.rs:69-124.

The shared timed ingress worker supplies signed native transactions to the pool.
Real native QS actors pull, cut, disperse, certify, store and repair batches.
NativeDissemination translates consensus payload requests and native exclusions.
When consensus identifies a commit, the adapter reserves application output
positions before spawning asynchronous payload retrieval. Materializer::resolve
releases only the contiguous ready prefix. Expansion is proof batches first,
then original subblock order. Raw duplicate/unknown occurrences remain evidence;
finite useful-request credit is separately deduplicated.

4. Parameter status and source index for PDF pages 4-5

CLI means exposed by the named runner today. JSON means an accepted configuration
field used by the node; it is not necessarily surfaced by that runner. FIXED
means source/profile-bound. A declared native field with inactive enforcement
is explicitly identified below. No single generic max_payloads field exists.

5. Recommended future experiment manifest (schema proposal only)

The following conceptual groups should be translated into each core's verified
effective configuration. They are not current accepted CLI/JSON aliases:

  identity: protocol, source/binary/profile hashes, committee IDs and host map
  workload: useful_tx_bytes, total_rate, origins, schedule, warmup/measure/drain
  batching: tx_per_batch, enforced_payload_bytes, cut_cadence, native policy
  proposal: tx/batch/reference limits, encoded bytes, witness/history budget
  transport: frame bytes, queue/window item+byte caps, retry/ACK/backpressure
  timing: injected_one_way_delay_ms, calibrated RTT evidence, protocol_Delta_ms,
          native timer mapping, optional materialization hold
  faults: tolerated_f (derived), actual faulty ID set, mode, target peers,
          bounded event schedule, activation/withdrawal and efficacy witnesses
  resources: CPU placement, runtime workers, memory/storage/network limits
  storage: backend/options, visibility/write/sync completion, restart semantics
  observation: full/compact, admission/output endpoints, unfinished accounting

Before cloud sweeps: wire common-node inventory/remote lifecycle; add sustained
Raptr workload support; expose intended limits and verify actual enforcement;
decide how to treat the inherited Raptr cap behavior; add multi-event faults.
Do not silently change native batching/consensus policy while adding controls.
